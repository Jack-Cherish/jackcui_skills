# 皮影戏动画（代码生成）

适用：用户想做一段皮影戏动画（历史串讲、故事短片等），要求“皮影要精致”、有字幕和配乐，最终要能播放和下载。

整体流程（按顺序，每步都有用户确认点）：
1. 写逐镜头脚本（Docs 文档）
2. 定画风：程序渲染 1–2 张样张给用户确认
3. 全片编排：逐幕画面 + 字幕
4. 逐镜头审片：重点查遮挡
5. 配乐：采样乐器离线混音
6. 交付：网页播放器（Artifact）+ MP4 视频

---

## 1. 脚本：必须逐镜头，不能只写分幕概述

用户若给了参考视频，先用 ffmpeg 抽帧（`fps=1,tile=4x2`）和裁出字幕条看清它的结构，再动笔。

脚本写成 Docs 文档，包含：
- 作品概况表（片名、时长、镜头数、视觉参考、叙事方式、主线意象）。
- **贯穿角色**：一个好奇的小角色（提问、惊叹）+ 一个引路者（讲述）。字幕一律是“角色名 + 台词”，不用脱离画面的旁白。
- **每一幕**：标题行带时间段，下面先写「本幕音乐」（主奏乐器、调式、BPM/拍子、情绪、参考曲），再写镜头表：镜号 | 时间 | 镜头景别 | 画面与皮影动作 | 字幕（角色 · 台词）| 音效。
- 字幕每条不超过约 22 字，停留时间不少于 2 秒。
- 历史人物尽量用真实名句；编写的台词在回复里说明是戏剧化处理。
- 首尾呼应的意象（如灯的点亮与熄灭、月亮的盈缺）。

3 分钟大约 14 幕、50 个镜头。

## 2. 画风：先出样张，用户确认后再做全片

**皮影 ≠ 扁平彩色矢量人物。** 用户会拿真实皮影照片纠正。要点：

- **幕**：一块纯色透光橙黄幕布，中央是油灯热点，四角压暗（radial gradient + 纸纹 overlay + 暗角）。不要画写实山水背景。
- **皮子**：以深色牛皮为底，红、绿、黄、蓝只是半透明染色块，颜色要偏深（如红 #7a120a、绿 #114428、黄 #946414）。
- **真镂空**：花纹是刻穿的孔，透出后面的幕光。做法是给每种“颜色 × 纹样”生成一个 CanvasPattern 贴图：先填染色，再在孔的位置描一圈深色刀口，最后用 `destination-out` 刻穿。纹样包括 flower、lattice、stripe（百褶）、tri（锯齿）、cloud、wave、scale、coin、dense。
- **阳刻边线**：每块皮子 clip 到自身路径后，依次描三道：深色宽线（bw×2）→ 透光细缝（bw×1.25）→ 深色（bw×0.95），形成“深-亮-深”的双线边，外缘再描一道墨线。
- **比例**：身形修长，头身比约 1:9（全身约 470 单位）。躯干窄直，下裳加百褶裙摆、蔽膝前襟、腰带玉佩流苏；女角加云肩、披帛、水袖。
- **空脸**：脸部刻空，只留侧面轮廓线（额头到鼻梁近乎一条线，用 bezier 画平滑），脸内基本透明。帝王、武将可用“实脸”（填深色，眉眼用透光色描）。
- **眼睛必须精致**：不能用等粗线条。
  - 柳叶眉 / 剑眉做成两头尖、中间厚的填充形。
  - 丹凤眼的上眼睑是填充形：内眼角细、中段粗、眼尾上挑入鬓，上方加一道细双眼皮线，下眼睑用细线。
  - 黑瞳贴着上睑，瞳上刻一个透光高光点。
  - 补鼻翼、唇线；女角加红唇和额间花钿；鬓角加发丝刻线。
  - 每次都单独渲染一张放大近景给用户检查眉眼。
- **头饰**：凤冠、冕旒、软脚幞头、展脚幞头/乌纱、方巾、双丫髻、盔+翎子、戏曲盔头等，都用镂空皮子画。
- **关节与签子**：关节处画铆钉（深色圆 + 透光小孔）；每个人偶画三根签子（脖颈一根、两手各一根），斜伸到幕下画外。
- **景片**：楼阁、树、祥云、船、城门等同样是镂空皮子刻法。离幕的远景画到半分辨率缓冲上再模糊、调淡，表现“离幕变虚”。
- **幕后柔影**：所有皮影先画到一个 layer，把 layer 缩小到 1/4、`source-in` 染深，放大后错位一点画在下面当作柔影，再叠上 layer。不要对整幅用 `ctx.filter blur`，太慢。
- **字幕条**：深褐色渐变横条，两端金色卷草和火焰纹；角色名用金色、台词用米白色，字体用 Noto Serif SC。

样张的做法：选一个代表性镜头（例如李白邀月）渲染全景一张、近景一张，用 SendUserFile 发出，并列出可调的项（明暗、花纹密度、身形瘦长），等用户确认后再往下做。

## 3. 全片编排（Canvas 2D，1920×1080）

文件结构（最后拼接成单个 HTML）：
- `core.js`：数学工具、纸纹、暗角、光尘、火焰、字幕条。
- `puppet.js`：镂空皮料、人偶装配、头茬、帽冠、手持道具。
- `scenery.js`：幕布、远景模糊层、人偶层、屋顶、楼阁、树、云、月、投影。
- `props.js`：各朝代的景片和道具。
- `acts.js`：角色预设表 CH、每幕的 draw(ctx, 幕内时间, 全局时间)、字幕表 SUBS。
- `engine.js`：按时间取幕、幕间 0.5 秒交叉淡化、后期处理、字幕。

编排要点：
- 人偶的姿态参数：手臂角度（从下垂算起，向前为正）、肘弯、头部倾角、身体前倾、走路相位。用 `mk(base, override)` 合并角色预设。
- 渲染必须是时间的纯函数（粒子用 hash），这样可以任意跳转，也能逐帧导出。
- 用无头 Chromium（Playwright）调用 `renderAt(t)` 截图，按每 3 张拼成一张总览图来检查。

## 4. 审片：遮挡规则（用户明确提过这个问题）

每个镜头的中点各渲染一帧，逐张检查：
- 人物背后只能是空幕，或者模糊变淡的远景。深色建筑或景片压在人物身后，会显得人被挡住或融在一起。
- 建筑放到两侧或远景层；人物之间、人物与道具之间要留出间距；行走的路线要错开。
- 不要用 clip 把人物下半身藏进车里、骆驼上或马背上（用户会认为是被遮挡）。改成人物站在车台上，或者在牲口前面步行。
- 两组以上人物同框时，检查整个时间段内会不会走到一起重叠。

## 5. 配乐：用采样乐器，不要振荡器硬合成

用 WebAudio 振荡器合成的民乐，用户评价“不好听”。正确做法：

1. 从 GitHub 下载 MIDI.js 音源（MusyngKite 质量较好），每个音一个 mp3：
   `https://raw.githubusercontent.com/gleitz/midi-js-soundfonts/gh-pages/MusyngKite/<乐器>-mp3/<音名>.mp3`
   音名写作 C4、Db4、Eb4……，只下载需要的音区，用 `xargs -P 16` 并行。
2. 乐器对照：
   - 板胡、京胡 → fiddle；二胡 → violin；马头琴 → cello
   - 埙 → ocarina；箫 → shakuhachi；笛子 → flute；骨笛、羌笛 → pan_flute
   - 唢呐 → shanai；筚篥 → oboe；胡笳 → english_horn；笙 → reed_organ
   - 古筝、秦筝 → koto；琵琶、三弦 → shamisen（琵琶轮指用快速重复音）；古琴 → acoustic_guitar_nylon（低八度，加滑音和吟猱）
   - 编钟 → tubular_bells；石磬 → kalimba
   - 战鼓 → taiko_drum；手鼓、羯鼓 → melodic_tom；拍板 → woodblock；驼铃 → agogo / tinkle_bell
   - 弦乐铺底 → string_ensemble_1；号角 → french_horn
   - 音效采样：seashore（水）、applause（喝彩）、gunshot（炮声）、bird_tweet
   - 锣、钹、火柴、裂纹等用 numpy 合成（非谐波分音、滤波噪声）。
3. 用 Python（numpy + scipy）离线混音：
   - 用 ffmpeg 把每个 mp3 解码成 44.1k float32。
   - 这些采样都是固定 3.1 秒长。持续音超过长度时，用 0.45–2.2 秒段交叉淡化循环延长。
   - 用时变重采样做滑音（从下方滑入）和揉弦。
   - 每个乐器设置音量、声像、混响量；混响用 fftconvolve 和生成的指数衰减脉冲响应。
   - 最后高通、tanh 软限幅，再用 `ffmpeg loudnorm=I=-17:TP=-1.5`。
4. 写谱：用简谱字符串 DSL（`3 5 6 1'- | 6 5 3 2--`，' 表示高八度、, 表示低八度、- 加一拍、_ 减半），配合 `mel()`、`arp()`、`perc()`、`roll()`、`tremolo()` 等函数。
5. 编曲：
   - 全片一个主题动机贯穿（序幕独奏 → 高潮全奏 → 升调全奏 → 尾声独奏）。
   - 每幕三层：主奏旋律 + 伴奏（拨弦琶音或弦乐铺底）+ 打击乐。
   - 音乐卡点对齐画面事件（编钟逐个敲响、炮声、火箭等），整片只留一处 2 秒静默。
   - 用频谱图（ffmpeg showspectrumpic）和分段 RMS 检查各段电平是否均衡。
6. 编码成 mp3（160k）后 base64 内嵌进页面。页面加载时就 decodeAudioData，播放时用 BufferSource.start(when, offset) 精确对齐画面；拖动进度时重新 start。

## 6. 交付

- **网页播放器（Artifact）**：标题 + 16:9 画布 + 首帧海报（选一个好看的镜头，中间放“开始放映”大按钮）+ 控制条（播放/暂停、时间、带幕刻度的进度条、当前幕名、静音、全屏）+ 十四幕章节按钮。单一深色剧场风格，手机宽度下章节改为 2 列。
- **MP4**：
  - 用 Playwright 多页并行导出帧：`renderAt(f/30)` 后取 canvas 的 `toDataURL('image/jpeg', .92)`。双核机器 5400 帧约 8 分钟。
  - 用 ffmpeg 合成：`-c:v libx264 -crf 20 -pix_fmt yuv420p -c:a aac -movflags +faststart`。
  - 1080p 约 115 MB，超过 SendUserFile 的 30 MB 上限。要另外两遍编码一个 720p 版：`scale=1280:720`，视频 `-b:v 1150k`，音频 112k，约 28 MB，发给用户下载。
  - 告诉用户还有 1080p 高清版，需要的话可以分段发。

## 常见坑

- 对 layer 或人偶使用 `ctx.filter`（blur、brightness）会让单帧耗时到数秒。模糊一律走“缩小缓冲 + 放大”或预渲染的 sprite（例如持签的手）。
- 修改场景函数时，不要整段替换到文件末尾，否则会误删后面的函数（如 crescent）。每次构建后都要跑全片截图检查。
- 预览环境连不上 Google Fonts，字体栈里要有本地兜底（Noto Serif CJK SC）。
- 镜像翻转（scale(-1,1)）带文字的景片时，文字会反过来，应该在另一侧单独再画一个。
