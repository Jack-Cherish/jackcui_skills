# 穿越多元宇宙 Skill

**同一个角色，一段横向旅程，走进完全不同的画中世界。**

这套技能让 Claude Code 或 Codex 按步骤制作画风切换短片：先确定主角和世界，再安排角色与场景的交互，用挥剑、裂缝等转场串起章节，最后加入音乐并导出视频。

技能调用名：`painting-traveler-video`

![梵高星夜风格场景：蓝色夜空、旋转星光与远处村庄](example/plates/plate_18.jpg)

*包内星夜风格背景板。下面的场景图、动作图和表情图都来自本包；背景板展示环境素材，成片制作时再叠加角色、动作与转场。*

## 你可以用它做什么

| 想做的内容 | 可以怎样展开 |
| --- | --- |
| 多画风冒险短片 | 每隔几秒进入一个新世界，让色彩、材质与动作节奏一起变化 |
| 个人角色展示 | 用你提供的原创动作表作为主角，比较同一人物在不同画风中的表现 |
| 美术风格巡游 | 将水墨、浮世绘、印象派、装饰艺术和像素世界编排成一条路线 |
| 有动作的小故事 | 不只横向行走，还可以停留、思考、跳跃、推拉、跌落和起身 |
| 配乐短片 | 为章节编排音乐与音效，让动作、转场和节奏互相配合 |

## 角色也会随世界改变

画风不仅体现在背景里。引擎还会改变角色的颜色、纹理、轮廓与渲染方式，让同一个动作在不同世界中呈现不同的视觉结果。

![同一个角色在多种画风下的效果对照](references/examples/ref_04.png)

*这是包内已有的画风对照图。图中列出的引擎风格与当前包实际保留的背景图不完全一一对应，制作时应先检查素材。*

## 主角动作：从走路到完整表演

### 侧面动作：待机、行走与挥剑

![角色侧面动作表：待机、行走与挥剑](references/heroine/ref_07.png)

这张图用于理解横版角色的基础动作结构。人物朝向、身高与脚底位置尽量统一，走路才不会忽大忽小，挥剑动作也能顺畅接到转场。洋红底是原始动作表的底色，制作时需要切图和处理背景。

### 正面动作：面对镜头的反应

![角色正面动作参考表](references/heroine/ref_08.png)

正面动作适合开场亮相、章节里的短暂停留，以及角色面向观众的反应镜头。不要让角色始终只用同一个侧面姿势滑过所有场景。

### 补充动作：让每个章节有事情发生

![角色补充动作表：思考、惊讶、指向、推拉与跳跃](references/heroine/ref_09.png)

可以用“发现目标 → 思考 → 接近 → 交互 → 离开”的短动作链组织一个章节。根据背景中实际存在的物体选择动作，避免手推到空处、落脚没有支撑或人物被景片遮住。

### 跌落与落地：把转场接成动作

![角色跌落、落地和起身的动作参考](references/heroine/ref_11.png)

跌落与落地可以把章节串起来：上一幕从高处离开，下一幕用落地动作接住，再恢复站立或行走。先确认现有动作帧能衔接，再确定镜头节奏。

## 一行安装


已安装 Node.js、Git，以及 Claude Code 或 Codex 后，在**终端**执行。此命令从仓库安装该技能到两个工具的用户技能目录：

```bash
npx -y skills add Jack-Cherish/jackcui_skills --skill painting-traveler-video -a claude-code -a codex -g --copy -y
```

如果使用的是这个本地包，可将整个技能文件夹复制到所需工具的目录，并将安装文件夹命名为 `painting-traveler-video`：

| 工具 | 用户技能目录 |
| --- | --- |
| Claude Code | `~/.claude/skills/painting-traveler-video/` |
| Codex | `~/.agents/skills/painting-traveler-video/` |

`~` 表示当前用户的主目录。安装后，该文件夹第一层应直接包含 `SKILL.md`、`scripts/` 和 `references/`。若技能未出现，重新打开工具。

## 开始使用

### 第一次尝试：先做一段短片

在 Claude Code 或 Codex 的对话框发送：

```text
使用 painting-traveler-video 技能，做一个30秒的穿越多元宇宙短片。
仅使用包内已有的角色和背景，不自动补图。
先检查素材，再给我3到4个世界的章节方案，每章安排一个明确的交互动作。
让我确认画风和节奏后，先出关键帧，再制作动画和配乐，最后导出 MP4。
```

### 已有自己的角色

```text
使用 painting-traveler-video 技能。主角使用我提供的原创角色动作表。
先检查待机、走路、挥剑和跳跃动作是否够用；缺少动作时先告诉我。
背景只从本包现有图片里选，先给我角色与场景的大小比例预览。
```

### 已经知道想要的画风

```text
使用 painting-traveler-video 技能，按“水墨 → 睡莲 → 星夜 → 像素”的顺序制作短片。
每个世界有一个动作停顿，最后回到开场。先列出实际会用到的图片路径，
再给我章节时长、动作和转场方案，确认后再渲染。
```

Claude Code 可以用 `/painting-traveler-video` 显式调用；Codex CLI 或 IDE 扩展可以用 `$painting-traveler-video`。也可以直接在对话中写出技能名称和需求。

## 从需求到成片，具体会做什么

| 阶段 | 需要确定的内容 | 先看什么再继续 |
| --- | --- | --- |
| 素材检查 | 哪些背景、角色动作和表情实际存在；运行依赖是否可用 | 可用素材清单与缺失项 |
| 主角设定 | 用包内角色还是自己的角色，角色尺寸、朝向与动作帧 | 单独角色预览 |
| 世界顺序 | 进入哪些世界、每章几秒、色彩怎样衔接 | 章节表 |
| 场景交互 | 骑乘、跳跃、观察、推拉等动作的目标和落点 | 每章关键帧 |
| 转场 | 挥剑时机、裂缝位置、进入下一幕的运动方向 | 前后两章衔接预览 |
| 配乐 | 主旋律、章节音色、交互音效与转场重音 | 试听与画面同步检查 |
| 导出 | 分辨率、帧率、目标体积与交付位置 | MP4 播放检查 |

## 环境与运行说明

安装技能只会让 AI 读取这套工作流，视频渲染还需要 Python、Playwright/Chromium、FFmpeg，以及 `requirements.txt` 中的 Python 包。

在技能目录中安装 Python 依赖：

```bash
python -m pip install -r requirements.txt
```

若尚未安装 Playwright 所需的 Chromium：

```bash
python -m playwright install chromium
```

**运行前先整理一个独立项目目录**：把 `scripts/` 中的工具和 `example/` 中所需的配置、素材复制进去，并核对 `film.json`。当前包经过精简，原示例有部分背景引用对应的文件已不在包内；需要改用现有背景并同步调整动作，不能直接假设原示例完整可运行。

准备好项目后，可在该项目目录使用这些命令：

| 命令 | 用途 |
| --- | --- |
| `python render.py sheet` | 检查角色在各画风下的效果 |
| `python render.py stills 1.0,7.3,13.9` | 在指定时间截图检查构图与动作 |
| `python score.py` | 根据项目配置制作配乐 |
| `python render.py video --workers 2 --mb 28` | 渲染并导出视频，设置并行数与目标体积 |

这些命令应在素材路径已核对、依赖已就绪后执行。视频耗时与章节长度、帧率、电脑性能有关。

## 常见问题

**只有一张角色立绘，也能用吗？**

可以先规划画风和镜头，但连续行走、挥剑等需要相应动作帧。让 AI 先列出缺少的动作，再决定简化动作还是由你另行提供动作表。

**为什么原始动作图和表情图有洋红色背景？**

它们是用于切图和处理背景的原始素材。角色进入成片前，需要检查切图结果，避免把洋红底一同带进场景。

**为什么 README 能看见某种画风，运行时却找不到对应背景？**

画风对照图展示引擎效果，实际背景文件以 `example/plates/` 为准。当前包有素材删减，先检查文件路径，再选场景。

**可以换成自己的故事吗？**

可以。先给出主角、时长、画风顺序和每章发生的事情。角色与图片请使用你有权使用的素材。
